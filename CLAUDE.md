# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this folder is

A Flask app, deployed as a static site that runs entirely in the browser, that turns a loan tape (CSV or xlsx), optionally with an expected-payments file and a received-payments file, into one finished Excel workbook: the `Portfolio` tear sheet plus analysis sheets (MOIC, COC vintage triangle, PAR, Concentration, Histograms) and the raw data as Excel Tables. Owned by a private credit associate at Addem Capital (LatAm / Mexico private credit). Git repo, deployed on Vercel from GitHub.

## Deployment (browser build)

There is no server and the deploy is one file. `public/index.html` is generated by `python source/build.py`, which embeds `source/worker.js` (as a text script turned into a Blob worker) and base64 copies of `source/py/app.py`, `bridge.py`, `template.xlsx` (written to the engine's disk as `Portfolio Analysis.xlsx`), `Theme1.thmx` and every wheel in `source/wheels/`. Edit files in `source/`, never `public/index.html`, then rebuild and commit both. `vercel.json` publishes `public/`; `.vercelignore` keeps `source/` out of the upload so Vercel never detects a Python app.

The worker boots Pyodide 0.27.7 from jsDelivr (the only external dependency), loads `sqlite3`, `pillow`, `markupsafe`, `jinja2` from the Pyodide distribution, unzips the embedded wheels into site-packages and imports `bridge.py`. `bridge.call()` drives the unchanged Flask routes through `app.test_client()`, so routes, globals and `build_workbook()` are the same code. `index.html` keeps the old `post()` contract but sends requests to the worker; after `/generate` it fetches `/download/<id>` into a blob URL and the bridge deletes the temp file. Because nothing is fetched from the host, the page also works opened straight from disk (`file://`).

Why one file: the first two Vercel deploys (2026-10-27) served `index.html` and `worker.js` but not the `public/py/` and `public/wheels/` subfolders (most likely never uploaded through the GitHub web UI), failing first as micropip "BadZipFile" and then as "py/app.py HTTP 404". Why in-browser at all: Vercel functions are stateless with a 4.5 MB request/response cap, which breaks the global-state design and real tapes, and in-browser keeps borrower data on the user's machine.

Upgrading a library means swapping its wheel in `source/wheels/` and rebuilding. Upgrading Pyodide changes the Python version (0.27 is 3.12); re-test.

Verified 2026-10-27 with Playwright (CDN routed to a local Pyodide copy, every URL but `index.html` returning 404, and again from `file://`): browser output identical cell for cell to native CPython on a synthetic 3,000-credit COC set; 16,000 credits, 112,000 expected and 98,141 received rows generate in about 42 s.

`Portfolio Analysis.xlsx` is the input template the app opens and writes into, so its formatting is load-bearing. `Theme1.thmx` is embedded into every output.

The app must stay generic across lenders. The user explicitly rejected lender-specific handling (e.g. PROMUJER's banca comunal): no hardcoded column names, no special cases, everything mapped in the UI or detected from the data.

## Commands

All Python lives in `source/py/`. The self-test runs on desktop CPython (`pip install flask==3.1.3 openpyxl==3.1.5 pillow`):

```bash
python source/py/app.py --selftest
```

`--selftest` is the only unit test: assert-based checks on number/date parsing, type detection, the dpd bucket partition and the blank-credit-id join rule. Run it after touching `parse_number`, `detect_type`, `BANDS` or `key_ok`. The old desktop server mode (`app.py --dev` on port 5000 serving `templates/index.html`) is retired: the page now only talks to the worker. To exercise the routes without a browser, use `app.app.test_client()` exactly as `bridge.py` does.

The team uses the Vercel URL. `Iniciar.bat` just opens `public/index.html` from disk (still needs jsDelivr for Pyodide). User guide and deploy steps in Spanish: `README.md`. When packaging for others, leave out `Data to Use/`, the xlsx tapes and the Quipu model: the tapes carry individual borrowers' full names.

Uploads go to `/upload?slot=tape|esperados|recibidos` as multipart `file`. Uploading a tape resets both payment slots. `/generate` takes `mode` (`tape` or `coc`), `saldo`, `dpd`, `summary`, `par`, `conc`, `hist`, and in COC mode `credit_id`, `orig`, `orig_date`, `dedupe`. It returns an id for `GET /download/<id>`.

Faster than the server for verification: import `app`, set `HEADERS`/`RAW`/`TYPES` from `read_table()`, call `rebuild()` and `load_pay()`, then call `build_workbook()` directly and inspect the saved file with openpyxl.

## Architecture

`source/py/app.py` holds everything; `source/index.html` is vanilla JS; the only build step is `source/build.py` bundling them.

**State.** Module globals: `RAW` (original tape text, never mutated), `HEADERS`, `TYPES`, `CALCS` (calculated columns as SQL expressions), `PAY` (payment-file metadata), plus one in-memory SQLite connection opened with `check_same_thread=False` because Flask serves each request on a new thread. `rebuild()` regenerates the typed `tape` table from `RAW` on every retype and replays `CALCS`, which is why a failed conversion reports its count and can be undone without data loss. Payment files load into their own `esperados` / `recibidos` tables via `load_pay()`, which keeps the raw rows in `PAY[slot]["raw"]` so `rebuild()` can reload them into the new connection (before 2026-10-27 a retype or calculated column after the payment uploads dropped both tables and `/generate` failed with "no such table: esperados").

**Payment column detection.** `pay_columns()` finds the payment file's id column by value overlap with the tape's credit id, not by name (`CodPrestamo NB` vs `Código de Préstamo`). Date is the first date column; amount is the first numeric column whose name contains "total", else the one with the largest sum.

**Grain.** Payments are keyed to the credit id, so COC mode rolls the tape up to one row per credit id on the `Credits` sheet before joining. For a one-row-per-credit tape this is 1:1; where a credit spans rows it stops each payment being counted once per row. The code makes no assumption about why.

**`build_workbook()` pipeline.** Load template, embed theme, write `Data` as an Excel Table, patch the `Portfolio` sheet, then in COC mode add Esperados, Recibidos, Credits, MOIC, COC; then PAR, Concentration, Histograms; finally reorder so analysis sheets come first and `Credits`, `Data`, `Esperados`, `Recibidos` sit at the end.

**Values versus formulas.** Every metric is a live formula over Excel Tables (`Data[...]`, `Credits[...]`, `Recibidos[...]`), so editing a number in the workbook recalculates. Keys are written as values: credit ids, `Cohort` (YYYYMM integer), `MoB` on Recibidos, attribute value lists, histogram bin edges. Editing a payment date therefore does not move it between MoB columns.

**Layout.** `OFF = 3`: every sheet has three spacer columns at width 1.29 and content starts at D. Always address columns through `L(i)` (logical 1 maps to D) and `column=i + OFF`; hardcoding a letter breaks the shift. Analysis sheets stack blocks vertically via `block_title()`; `collapse()` groups a block's rows at outline level 1 but leaves them expanded on open, with a spacer row after each block so the outline control lands correctly.

## Generated sheets

- `Portfolio`: the template. Summary rows 14 to 19 are the user's dragged columns with `MIN`, `MAX` and a saldo-weighted average (`SUMPRODUCT/SUM`, header relabelled "Wtd. Average"). Buckets `J15:J21` / `L15:L21` get `SUMIFS`/`COUNTIFS`. Rows 23 to 24 are Active Total Credits and Outstanding Balance; rows 25 to 27 and the Borrowing Base panel `O11:Q21` are cleared.
- `MOIC`: cohort Originated / Received / Cohort MOIC (summed received over summed originated, so value weighted) plus a 0 to 2.0x distribution in 0.1 steps with an above-2.0x overflow row.
- `COC`: the MoB vintage triangle (Month of Cohort, Disbursed, # Credits, then cumulative MOIC by months on book, each row stopping at months elapsed), with calendar-month collections below it.
- `PAR`: one sheet, one block per dragged attribute, PAR 7 / 15 / 30 by balance and count.
- `Concentration`: per attribute, top 20 by outstanding plus Other and TOTAL, with cumulative share.
- `Histograms`: 12 bins per column, edges fixed at generation, counts live.
- `Auditoría de Datos` (always generated, Spanish): diagnosis line, `Riesgos Inmediatos` controls, `Optimizaciones de Rendimiento`, a per-column `Perfil` of every table in the workbook, and blue `Supuestos` inputs every threshold reads from. A tape declares no `NOT NULL` or `VARCHAR` limits, so the schema is inferred: usage is measured against naive-import defaults (`VARCHAR(255)`, `INT`, `DECIMAL(18,2)`) and Excel's ceilings (1,048,576 rows, 15 digits). Facts that exist only at load time (empty rows dropped by `read_table` into `EMPTY_ROWS`, payment orphans and duplicates computed in `build_workbook`'s `pst`, case variants) are written as blue values; everything else is live. Controls that reference `Esperados`/`Recibidos`/`Credits` are emitted only when those tables exist, so tape-only files reference `Data` alone.

## Rules that are easy to break

- `parse_number`: a lone `.` is always a decimal point; only repeated dots mean thousands grouping. The earlier "three digits after the dot is thousands" rule multiplied `0.425` by 1000. The shape regex runs before separators are stripped, otherwise `18/09/2026` becomes `18092026` and date columns detect as integers.
- A blank days-past-due means current: the first bucket formula also matches `""`. The seven `BANDS` partition every integer and the self-test asserts it.
- Expected payments are de-duplicated with `DISTINCT` (PROMUJER's file is two stacked extracts, about 23% inflated otherwise). Received payments must never be: identical rows are real separate payments.
- The triangle's cohort label is a real date so Excel renders "January 2025", but the stored key is the YYYYMM integer, so criteria rebuild it as `YEAR($D5)*100+MONTH($D5)`. A text or date key silently matches nothing in `SUMIFS`.
- `theme_xml()` forces `dk1` (Text 1) to `1F1F1F` when it is too light. The supplied theme sets it to pale green `AFEAC1`, and Excel's Normal style is theme colour 1, so default text rendered near-invisible.

## openpyxl pitfalls hit here

- A chart plots hidden rows only with `chart.visible_cells_only = False`. Setting `plotVisOnly` does nothing.
- `bar += line` keeps the line series on `line.series`; paint them there before combining, `bar.series` only holds the bars.
- openpyxl writes chart XML without the `c:` prefix, so grepping for `<c:plotVisOnly` gives false negatives.
- Unpainted series let Excel cycle theme accents. Every series goes through `paint()` and every chart through `style_chart()`.
- openpyxl keeps the template's drawing (the logo); only re-add it if `ws._images` is empty, or it duplicates.
- Dynamic-array functions go in as `ArrayFormula` with Excel's own prefixes: `_xlfn.UNIQUE`, `_xlfn._xlws.FILTER`, `_xlfn._xlws.SORT`. Guard empty inputs with `IF`, not `IFERROR`, so an Excel without them shows `#NAME?` instead of a believable 0. `UNIQUE` ignores case. Refer to a whole table as `Data[#Data]`, never a bare `Data`.
- Array-forcing without `ArrayFormula`: wrap in `SUMPRODUCT`, e.g. `SUMPRODUCT(MAX(LEN(T[c])))`. Never write the `[@Col]` shorthand into a formula; it is UI-only and corrupts the file.
- Formula text built from templates must address cells through `L(i)`. The audit tab's first version hardcoded `D{r}` in its evidence sentences and every one printed the Área label instead of its number, because the margin had moved the metric to G.

## Formatting

One palette, defined as constants from the theme (`DEEP 0C473C`, `MID 4A655C`, `PALE 9CC7B6`, `INK 1F1F1F`, `SAND D1C6BF`). All conditional formatting goes through `scale()` (pale `E8F3EE` to `9CC7B6` to `4A655C`, capped at MID so text stays readable) and `databar()` (`9CC7B6`). Data bars exclude TOTAL rows so one large row does not flatten the rest. House cell style on the template: Helvetica 8, hardcoded inputs blue `#0432FF` on pale yellow `#FCFFBD`, formulas black on no fill.

## UI

`index.html` flow: scope (Tape analysis, or Tape analysis + COC which reveals the two payment slots, the dedupe checkbox and three extra mappings), per-column type dropdowns on draggable bubbles, SQL calculated columns (names with spaces or accents need double quotes), then drop zones for Summary (max 6, ordered), PAR, Concentration and Histograms. All requests go to the embedded worker, never over HTTP.
